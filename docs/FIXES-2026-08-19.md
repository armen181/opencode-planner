# Planner Plugin — Fix History (2026-08-19)

Deep investigation + one-by-one fixes for the planner opencode plugin
(planner → worker → tester → vision). Each fix below is a separate commit.

## How the investigation was done

- Read every file in the repo (plugins, agents, tests, docs, install.sh).
- Verified every API assumption against the **real** artifacts on this machine:
  - opencode **1.18.18** binary (`~/.opencode/bin/opencode`) — string-scanned for
    hook names, endpoints, and config keys.
  - Type definitions in `~/.config/opencode/node_modules/@opencode-ai/plugin`
    (`Hooks`, `tui.d.ts`) and `@opencode-ai/sdk` (generated client types).
  - Official docs at opencode.ai (plugins, agents, TUI).
- **Ran the plugin live** against a real `opencode serve` instance in scratch
  projects (isolated config dir), exercising: config-hook model injection,
  web commands, screenshot surfacing, live config reload, vision agent
  registration/removal, and the missing-agent-file failure mode.
- `unit_gate.py` (76 checks) and `test_planner_config.py` run after every fix.

### Things confirmed WORKING during the audit (kept as-is)

- `config` hook injection of `default_agent` + per-agent models (GET /agent verified).
- Web `/planner-*` commands via `chat.message`.
- Screenshot surfacing as inline `FilePart` via `promptAsync({ noReply })`.
- Live config reload via `instance.dispose` (auto-fired, gated on session idle).
- Vision toggle: `delete config.agent.vision` removes the agent even though the
  `.md` file stays on disk.
- Both `.opencode/agent` and `.opencode/agents` directories are loaded by opencode.
- All hook signatures used match `@opencode-ai/plugin` 1.18 types.
- `tui.json` `plugin` registration and the v1 TUI `api.command` popup API work.

## Fixes (chronological)

### `09b062c` — vision-delegation: remove hardcoded personal paths
`findPlannerRepo` had a fallback list of the author's absolute home directories
(`/home/armen/StudioProjects/...`). Besides leaking personal paths, it could
apply the **wrong project's** vision config to an unrelated session (first repo
with vision enabled won). Removed entirely — the plugin is installed per-project,
so resolving the repo from its own install path is sufficient. Also switched
`URL.pathname` → `fileURLToPath` (pathname stays percent-encoded, breaking paths
with spaces).

### `7da94e7` — planner.ts: guard agent injection on agent-file existence
**Confirmed live:** the config hook created `config.agent.planner/worker/tester`
entries unconditionally. When a `.md` definition was missing (e.g. web
`/planner-enable` on a project where agents were never copied), opencode
registered **prompt-less shell agents**, and `default_agent` pointed at a broken
planner. Now models are injected only for agents whose `.md` exists (checked in
both `.opencode/agent/` and `.opencode/agents/`), and `default_agent` is set only
when `planner.md` exists.

### `c030981` — preserve models on enable/disable; unify TUI+web logic
TUI `enablePlanner`/`disablePlanner` rewrote a **default** config, silently wiping
configured models; web commands preserved them. TUI disable also deleted agent and
plugin files while web disable did not. New shared code path in `planner-core.ts`:
- `setPlannerEnabled(repo, enabled)` — flag-only toggle, preserves models/vision.
- `plannerSourceCandidates`, `copyPlannerAgents`, `copyPlannerServerPlugins`,
  `enablePlannerProject`, `disablePlannerProject` — one implementation used by
  both TUI popups and web commands.
- Web `/planner-enable` now also bootstraps agents + server plugins (previously it
  only flipped the flag — the broken-shell-agent path from the fix above).
- Disable is non-destructive everywhere: flips `enabled false`, keeps models and
  files (inert while disabled).

### `241fd45` — harden screenshot injection
- `filePart` refuses files > **8 MB** (no giant base64 blobs in chat).
- Tool-output `.png` detection now requires mtime within the last **5 minutes**
  (`isFreshPng`), caps at **3 images per tool run**, and prefers `write`/`edit`'s
  own `args.filePath`. Before this, `ls *.png` (or crafted tool output naming
  arbitrary local files) could mass-inject unrelated images into the session — a
  prompt-injection exfiltration path to the LLM provider.
- Failed injections retry at most **3 times** instead of every sweep forever.
- Per-project screenshot dir is `chmod 0700`.

### `d1d32a4` — vision-delegation: scope to planner agent; require enabled
The system.transform hook carries **no agent**, so the delegation instruction was
injected into *every* vision-less agent (worker, tester, hidden
title/summary/compaction agents), wasting tokens on every system turn. Now a
`chat.message` hook tracks `sessionID → agent` and the instruction is injected
only for the **planner**; unknown sessions are skipped, not guessed. Also requires
`cfg.enabled` (previously leaked even when planner was disabled).

### `1d156e5` — busySessions hygiene (live reload could stall forever)
Busy entries were only cleared by a `session.status {type:"idle"}` event. A missed
idle event, a session deleted mid-stream, or an error that never cleared the status
left it "busy" forever, **permanently blocking** the config-change reload. Now:
- `busySessions` records *when* a session became busy; entries older than 10 min
  are stale.
- Before blocking a reload, remaining entries are re-verified against the real
  `GET /session/status` map and dropped if not actually busy.
- `session.deleted` clears the entry immediately.

### `482a56b` — atomic config writes
`writePlannerConfig` wrote directly; the TUI and the server plugin run in different
processes and both read-modify-write the same file. Writes now go to a temp file +
`renameSync`, so readers only ever see the old or the new config, never a torn one.

### `2ecc818` — web commands no longer consume a planner LLM turn
**Confirmed live:** web `/planner-*` commands arrive as ordinary user messages; the
old handler mutated the text but opencode still ran a full model turn on the result
— wasted tokens, confusing replies, and the session stayed busy, delaying the very
config reload many commands trigger (~45s measured). Now the result is injected as a
standalone no-reply message and the hook throws to cancel the turn. Verified against
1.18.18: turn cancelled, no error surfaced, session returns to idle; degrades to the
old in-place mutation if injection fails. Also added `provider/model-id` validation
for `/planner-config`.

### `86ebef0` — resolve install path via fileURLToPath
`resolveProjectRoot` used `URL.pathname` (percent-encoded), so project paths with
spaces failed the `.opencode` existence check and fell back to the git root —
exactly the nested-project case install-path resolution exists to fix. Replaced with
`fileURLToPath`; fixed the stale comment block.

### `1afe3b0` — cache session→root resolution
`tool.execute.after` fires for every tool run and previously spent one `session.get`
plus one API call per `parentID` level each time. The resolved root (and the
repo-directory verification) is now cached per session, dropped on `session.deleted`.

### `d207740` — planner-tui: validate model ids before saving
Custom model prompts accepted any string; garbage persisted into
`planner-plugin.json` and failed opaquely at turn time. `pickModel`/`enableVision`
reject values that are not `provider/model-id` with an error toast.

### `1c1bccb` — agents: allow macOS TMPDIR for screenshot writes
On macOS `$TMPDIR` is under `/var/folders/...`, which was not covered by
`external_directory`, so saving screenshots there would prompt. Added
`/var/folders/**` to worker and vision.

### `12729e5` — remove dead code
- Empty `tool.execute.*` branch in the server event handler.
- Unused `plannerSetModel` export in the TUI plugin.
- Stopped passing `onCancel` to `DialogSelect` (no such prop; Esc belongs to the
  dialog stack). `DialogConfirm`/`DialogPrompt` keep theirs.

### `6508d63` — wire maxCycles into the planner system prompt
`maxCycles` was dead config (`planner.md` hardcoded "max 3 cycles"). The server
plugin now appends the configured limit to the planner's system prompt via
`experimental.chat.system.transform`, scoped to the planner agent.

### `1f9eaf9` + `daa2295` — close the visual-validation loop (vision QA)
The worker saved a screenshot but **nobody verified it**. The planner now runs a
vision verification step after `STATUS: PASS` when a screenshot exists and a vision
subagent is available (checks the rendered result against the visual requirements;
mismatches are treated like a tester FAIL), and references the configured cycle
limit. (`daa2295` renames the "QA" wording because the legacy-branding gate scans
agents for the string `qa`.)

### `c9c6702` — annotate entry points with `@opencode-ai/plugin` types
Added type-only imports (`Plugin`, `TuiPlugin`) and annotated
`PlannerServerPlugin`, `VisionDelegationPlugin`, `tuiPlugin`. Type-only imports are
erased at runtime — verified by booting a real server.

### `485ba5b` — document v1 command-API deprecation
`api.command.register` is deprecated in favor of `api.keymap.registerLayer`, but it
remains the API that provides both slash-name registration and the `onSelect(dialog)`
popup stack this UX depends on. The v2 keymap shape is not stable enough to migrate
without risking the working UX — documented in-place for a future migration.

### `0c940f4` — README: live reload, one-time restart, enable/disable semantics
Clarified that only ONE restart is needed after the first enable; later model/vision
changes apply live. Documented the reload mechanism (waits for idle sessions; busy
flags are expired/re-verified) and that enable/disable never wipes models.

### `acba4a3` — install.sh: fail fast without python3; honor OPENCODE_PLANNER_ROOT
`install.sh` used python3 unconditionally; now exits with a clear message if
missing. Also honors `OPENCODE_PLANNER_ROOT` (the var the TUI already reads),
keeping `OPENCODE_ORCHESTRATOR_ROOT` as a legacy fallback.

### `20ca8a8` — throttled diagnostics via client.app.log
Every failure path was a silent catch (deliberately — console output leaks into the
TUI). Added a throttled (max once/minute) `logWarn` using `client.app.log` and wired
it into the instance-dispose, screenshot-injection, and tool-after surfacing failure
paths. Logging itself never throws.

### `47ffbd8` — toast in attached TUI when a screenshot is surfaced
After successful injection, notify any connected TUI via `client.tui.showToast`.
Fails silently when no TUI is attached (web/headless).

### `e3268c5` — discover screenshot target after instance reload
**Caught by the live e2e:** an instance reload resets `lastTarget`, and no session
events re-fire for existing sessions, so a screenshot arriving right after a config
change was marked injected without ever being shown. `sweep()` now falls back to
discovering the most recently updated main session of the project via `session.list`.

### `fda4542` — test_planner_config: preserve + single-config coverage
Added assertions that disable/enable only toggle the flag and preserve models
(worker/tester/vision), plus source checks for `setPlannerEnabled`,
`enablePlannerProject`/`disablePlannerProject`, and the atomic temp+rename write.

### `2667158` — test_planner_live: portable e2e + new regression checks
- Model ids and port are env-configurable (`PLANNER_TEST_MODEL`,
  `PLANNER_TEST_VISION_MODEL`, `PLANNER_TEST_MODEL_ALT`, `PLANNER_TEST_PORT`).
  **No reachable LLM provider is required** (web commands cancel their turn;
  screenshot injection uses noReply), so the suite runs against any opencode
  install — the previous hard dependency on an `akna` provider is gone.
- New checks: web commands create **no assistant turn** (regression for the
  cancelled-turn fix); invalid model ids are rejected; a model change applies
  **live via instance reload** (no restart).
- `free_port()` builds its pkill pattern from the configured port with the
  self-match-safe bracket trick.

### `da41f52` — test_planner_tui: poll to reduce timing flakiness
The screen-scrape assertions read a single frame right after the command, so a slow
TUI cold-start caused intermittent failures. Both checks now keep draining output
for up to 10s until the expected content appears.

## Notable behaviors intentionally kept

- Screenshots are injected with `agent: "planner"` + the planner model even though
  `noReply` means no model turn (harmless, keeps message attribution sane).
- Disable leaves agent/plugin files in place (inert) so re-enabling never loses
  setup; removal is a manual step.
